# Examples

Three reference deployments showing what `just build` produces for realistic project
configurations. Each example has the standard `.crews/` triad config plus the
generated `.kiro/` output that ships from it.

| Example | Crews | Agents | Stack |
|---|---|---|---|
| `godot-game` | `general` + `bug-fix` + `content` | 28 | Godot game project (pixel-dungeon) |
| `node-webapp` | `general` + `bug-fix` + `infrastructure` | 29 | Node/TypeScript web app (taskflow-ui) |
| `rust-cli` | `general` + `bug-fix` + `rust` | 26 | Rust CLI (ferris-tracker) |

These compositions are deliberately realistic — small-team-or-solo crews you'd
actually run, not the full 78-agent catalog wired up. Use them as templates when
authoring a new `.crews/crew.yaml`.

## What's in each example

```
.crews/
  crew.yaml         Source-of-truth project config (commit this)
.kiro/              Generated runtime (regenerated by `just build`)
  agents/             Agent JSON files kiro-cli loads
  prompts/            User-invokable prompts (handoff, read-handoff, grill-with-docs, crew-sheet)
  steering/           Always-loaded behavioral rules
  skills/             On-demand knowledge
  scripts/            Utility scripts contributed by behavior components
```

## Rebuilding

From the agent-crews repo root:

```sh
just build --all       # base crews + all examples + every fleet.local project
```

To deploy one of these crews to a real project, write its `.crews/crew.yaml`,
register the project in `fleet.local.yaml`, then `just build <project>`.
